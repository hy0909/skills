# 프로토타입 구현 기준

단일 HTML 프로토타입의 구조·상태·패턴 표준. 다음 프로토타입도 이 기준 그대로 만들면 된다.

## 1. 파일 구조 (위에서 아래 순서)

```html
<meta charset="utf-8">                <!-- 필수 — 없으면 로컬 서버에서 한글 깨짐 -->
<title>서비스명 도메인 프로토타입</title>
<style>
  @font-face { Pretendard Variable — base64 data URI, font-weight:45 920 }
  :root { 디자인 토큰 CSS 변수 — references/design-tokens.md }
  /* reset → 앱 프레임 → 컴포넌트 → 페이지 → 모달 → 프로토타입 컨트롤 순 */
</style>
<div id="app"></div>                  <!-- GNB + 타이틀바 + 페이지: 전체 재렌더 -->
<div id="modal-root"></div>           <!-- 모달 레이어: 별도 렌더 -->
<div id="toast" class="toast"></div>  <!-- 토스트: 고정 1개 -->
<div class="proto-ctl">…</div>        <!-- 권한 토글 + 데모 가이드 (재렌더 밖) -->
<script> 아이콘 → 시드 데이터 → 상태 → 렌더 함수 → 이벤트 위임 </script>
```

- Artifact 배포를 겸하므로 `<!doctype>`·`<html>`·`<head>`·`<body>` 태그는 쓰지 않는다(래퍼가 붙여줌).
- 외부 요청 0개: 폰트 임베드, 아이콘은 lucide 인라인 SVG, 이미지(QR·제품 썸네일)는 SVG/CSS로 생성.

## 2. 상태 모델 — 권한 동기화가 핵심

```js
const state = {
  role: 'user' | 'admin',   // 프로토타입 컨트롤로만 변경
  page: '...',              // GNB 라우팅 (권한별 메뉴 구성은 다르게, 데이터는 공유)
  orders: [...], groups: [...],  // ★ 단일 원본 — 두 권한이 같은 배열을 본다
  kebab / ddOpen / search / 모달상태 ...
};
```

- 도메인 객체는 **상태 enum 하나**(예: `pending|approved|rejected|canceled`)로 두고,
  권한별 표기(승인 대기 중/승인함, 반려됨/거절함, 취소함/사용자가 취소)는 **렌더 함수에서 매핑**한다.
- 플로우 액션(승인·거절·취소·발주)은 이 원본 배열만 바꾼다 → 권한을 전환하면 반대편 화면에 반영돼 있어야 한다.
- 승인처럼 "다른 목록에 리소스가 생기는" 규칙(발주 승인 → QR 그룹 생성)도 실제로 groups에 push한다 —
  이런 교차 화면 효과가 프로토타입의 핵심 설득 포인트다.

## 3. 렌더링

- 상태 변경 → `render()` 전체 재렌더(innerHTML). 프로토타입 규모에선 이게 제일 단순하고 안전하다.
- 예외 2가지만 부분 처리: ① 검색 인풋은 재렌더 후 포커스·커서 복원 ② 모달 안 수량 인풋은
  `change`(blur) 시점에만 정규화 — 타이핑 중 재렌더하면 포커스를 잃는다.
- 이벤트는 `document` 위임 + `data-act` / `data-nav` / `data-dd` / `data-set` 속성으로만 바인딩.

## 4. UI 패턴 표준

| 패턴 | 기준 |
| --- | --- |
| 확인 모달 | 제목 18 bold + 본문 15 + [보조(아웃라인)] [주action] 중앙 정렬. 위험 액션(거절·취소·삭제)은 `--red-600`, 확정 액션은 `--gray-900` 다크 |
| 토스트 | 다크(`--gray-900`) 필, 화면 중앙 상단 고정(`position:fixed; top:타이틀바 아래`), 2.6초 후 사라짐. 문구는 스펙 그대로 |
| 셀렉트 | 커스텀 드롭다운(제품처럼 썸네일 들어가는 옵션 때문에 네이티브 select 금지). 한 번에 하나만 열림, 바깥 클릭 시 닫힘 |
| 케밥 메뉴 | 행 우측 ⋮ → 앵커 기준 드롭다운. 권한·상태별 메뉴 구성은 스펙 그대로 |
| 상태 칩 | 대기=primary filled+x, 완료=아웃라인, 거절=pink600 텍스트, 취소=gray100 칩 (프로젝트 스펙 우선) |
| 종결 행 | 행 전체 텍스트 `--gray-400`, ID 빈값, 다운로드류 버튼 disabled |
| 목록 스크롤 | GNB·타이틀·필터바·페이지네이션 고정, 목록 영역만 `overflow-y:auto` (flex column + min-height:0) |
| 레이아웃 폭 | **배경색(GNB·타이틀바·본문)은 풀블리드로 좌우 무제한**, 콘텐츠(텍스트+안쪽 패딩)는 `max-width:1440px` 중앙 정렬. 공용 `.shell{max-width:1440px;margin:0 auto;width:100%}`을 각 바(bar)의 안쪽 래퍼로 쓴다 |
| 빈 상태 | 범위 외 메뉴는 "이 화면은 프로토타입 범위에 포함되지 않아요" 빈 상태로 |

## 5. 프로토타입 컨트롤 (데모 전용 UI)

- 좌하단 플로팅 카드, 실서비스 UI와 확실히 구분되는 라벨("권한 보기 (프로토타입 컨트롤)").
- 권한 세그먼트 토글 + 접을 수 있는 "데모 가이드"(봐야 할 플로우 4~5개 목록).
- 권한 전환 시: 기본 페이지로 이동, 열린 모달·메뉴·검색 초기화. **데이터는 절대 리셋하지 않는다.**

## 6. 입력 검증은 스펙 숫자 그대로

예: SafeQR 발주 수량 — 기본·최소 10,000 / 1만 단위(하위 4자리 0 강제) / 콤마 자동 / 총합 최대 600,000 인풋 컷 /
최소에서 [-] disabled / 행 최대 5개(도달 시 추가 버튼 disabled) / 초과 시도 시 빨간 안내 텍스트.
"대충 비슷하게"를 금지하는 이유: 개발자가 이 프로토타입을 보고 검증 로직을 구현한다.

## 7. 검증 체크리스트 (배포 전 브라우저에서 전부 클릭)

- [ ] 한글 정상(meta charset), 콘솔 에러 0, Pretendard 로드(`document.fonts.check`)
- [ ] 피그마 원본 스크린샷과 화면별 비교 — 색·간격·칩 모양·버튼 상태
- [ ] 해피 플로우: 작성 → 검증 컷 → 실행 → 토스트 → 목록 반영
- [ ] 교차 권한: A 권한에서 액션 → B 권한 화면에 반영
- [ ] 엣지: 최소/최대값, disabled 상태, 종결 행, 빈 상태 페이지
- [ ] md ↔ 시안 표기 충돌 목록을 최종 보고에 포함

## 8. 전달

1. HTML 파일 자체 (더블클릭으로 열림)
2. Claude Artifact 배포 → 팀 공유 링크 (갱신은 같은 URL로 재배포)
3. 이 레포 `examples/`에 커밋 — 다음 프로토타입의 참고 예제가 된다
