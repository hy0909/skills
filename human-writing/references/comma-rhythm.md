# 쉼표와 문장 구조를 함께 고친다

사용 범위: 쉼표·문장 리듬을 고치는 요청, 비슷한 길이의 절을 잇는 틀이 반복되는 초안.
검토일: 2026-09-17. 정리: hy0909.

## 무엇을 문제로 보는가

이번 개선 대상은 ‘길이가 유사한 문장 사이에 쉼표’가 반복되는 글이다. 한 문장 안에서는 쉼표 앞뒤의 서술어가 있는 덩어리를 ‘절’이라고 부른다. `A하며, B한다. C하며, D한다.`처럼 매번 두 절을 비슷한 분량으로 붙이면 설명 내용이 달라도 리듬이 같아진다.

길이가 비슷한 것과 읽기 어려운 것은 다르다. 실제 비교나 조건을 나타내는 문장은 대칭 구조가 잘 맞을 수 있다. 교정할 때는 앞뒤 절의 관계와 문단에서 같은 구조가 반복되는 이유를 확인한다. 이 기준은 사용자 선호를 반영한 편집 기준이며 AI 작성 여부를 판정하는 공식이 아니다.

논문은 에세이·시·논문 초록과 네 LLM을 대상으로 한다. 한국어 업무 문서 전반이나 이후 모델에서도 같은 결과가 난다고 단정할 수 없다. 특히 ‘쉼표 앞뒤 길이가 비슷한가’를 직접 검증한 연구로 인용하지 않는다.

검색한 교정 사례 중에는 쉼표를 줄이면서 내용을 새로 넣은 예가 있었다. 이 스킬은 문장 분리라는 방법만 참고한다. 구체적으로 보이게 하려고 원문에 없는 사례를 더하지 않는다.

## 기존 규칙이 반복을 만들 수 있는 지점을 고친다

| 기존 지침 | 생길 수 있는 문제 | 바꾼 기준 |
| --- | --- | --- |
| `~습니다`가 세 번이면 문장을 잇거나 질문형 사용 | 독립된 설명을 `~고, ~합니다`로 계속 합침 | 어미 반복은 점검 신호. 자연스러우면 보존 |
| 대조·원인·조건·나열은 한 문장에 연결 | 모든 문장을 두 절로 맞추는 틀로 굳어짐 | 관계를 함께 읽어야 할 때만 연결 |
| 짧은 문장 뒤 `하지만`은 나쁜 리듬 | 분리해도 되는 긴 설명까지 합침 | 연결어 자체보다 앞뒤 관계가 명확한지 판단 |
| 상세 목록에만 ‘쉼표 남발’ 명시 | 지울 쉼표와 남길 쉼표를 구별하기 어려움 | 본문에 판단 순서 추가, 수정·보존 예시 연결 |

## 앞뒤 뜻을 보고 수정 방법을 고른다

1. 쉼표가 열거·숫자·인용·코드 안에 있으면 먼저 보존한다. 오독을 막거나 의도한 대조를 드러내는 쉼표도 남긴다.
2. 문단에서 `비슷한 길이의 절 + 쉼표 + 비슷한 길이의 절`이 같은 연결어미와 함께 반복되는지 읽는다. 한 번 등장한 자연스러운 문장은 그대로 둔다. 글자 수나 길이 비율을 합격 기준으로 삼지 않는다.
3. 관계가 연결어미만으로 분명하면 쉼표만 뺀다. 다른 주제·주체의 독립된 설명이면 나눈다. 주어나 서술어가 겹치고 같은 기준을 설명하면 공통 부분을 묶는다. 조건이 뒤의 여러 행동에 걸리면 그 범위를 유지한다.
4. 고친 문단을 다시 읽는다. 쉼표만 없어졌을 뿐 같은 틀이 계속되면 문장 구조를 재검토한다. 리듬을 바꿀 명분으로 새 주장·원인·사례를 만들거나 문단 순서를 바꾸지 않는다.
5. 누가 무엇을 하는지, 언제·어떤 조건인지, 부정·가능성·의무의 뜻이 같은지 원문과 대조한다. 뜻이 달라졌거나 덜 자연스러우면 되돌린다.

## 수정과 보존을 함께 연습한다

아래 예문은 교정 기준을 설명하기 위해 만든 예시다. 웹 자료의 문장을 옮긴 것이 아니다. 정답 문구를 외우지 말고 수정 이유와 보존할 뜻을 확인한다.

| 경우 | 원문 | 가능한 결과 | 판단 이유 |
| --- | --- | --- | --- |
| 쉼표만 삭제 | 초안을 읽고, 의견을 적는다. | 초안을 읽고 의견을 적는다. | 행동 순서가 어미만으로 분명 |
| 독립된 설명 분리 | 보고서는 오늘 마감하며, 설명회는 내일 시작한다. | 보고서는 오늘 마감한다. 설명회는 내일 시작한다. | 서로 다른 일정이며 원인·조건 관계 없음 |
| 공통 성분 묶기 | 제목은 짧게 쓰고, 설명도 짧게 쓴다. | 제목과 설명은 짧게 쓴다. | 같은 서술어와 기준을 공유 |
| 조건 보존 | 승인이 나면, 파일을 공개하고 링크를 보낸다. | 승인이 나면 파일을 공개하고 링크를 보낸다. | 공개와 발송 모두 승인 조건에 걸림 |
| 원인 보존 | 권한이 없어서, 파일을 열 수 없다. | 권한이 없어서 파일을 열 수 없다. | 원인과 결과를 함께 유지 |
| 실제 대조 보존 | 관리자는 파일을 수정하고, 방문자는 파일을 읽는다. | 원문 유지 가능 | 권한 차이를 비교하는 대칭 구조 |
| 열거 보존 | 이름, 부서, 이메일을 입력한다. | 원문 유지 | 항목 경계를 표시하는 쉼표 |
| 오독 방지 | 철수가 울면서, 떠나는 영희를 배웅했다. | 원문 유지 | 우는 사람이 철수임을 분명히 함 |
| 숫자·인용 보존 | 요금은 1,500원이다. 안내문에는 “확인하고, 제출하세요.”라고 적혀 있다. | 원문 유지 | 숫자 표기와 직접 인용 보호 |
| 자연스러운 단문 보존 | 초안은 오늘 제출합니다. 검토는 내일 시작합니다. 결과는 금요일에 알립니다. | 원문 유지 | 날짜별 안내가 명확함. 어미 횟수만으로 합치지 않음 |
| 비슷한 길이만 일치 | 제목은 짧게 쓴다. 설명은 쉽게 쓴다. | 원문 유지 | 길이만 같다는 이유로 변형하지 않음 |
| 가능성·의무 보존 | 검토가 늦어질 수 있으며, 제출일은 지켜야 한다. | 검토가 늦어질 수 있다. 제출일은 지켜야 한다. | 가능성을 확정으로, 의무를 사실로 바꾸지 않음 |

### 문단 전체에서 같은 틀이 반복될 때

원문:

> 초안은 오늘 작성하며, 검토는 내일 진행합니다. 의견은 문서에 기록하며, 질문은 댓글에 남깁니다.

가능한 수정:

> 초안은 오늘 작성합니다. 검토는 내일 진행합니다. 의견은 문서에 기록하고 질문은 댓글에 남깁니다.

앞 문장은 다른 날의 작업을 나눴고 뒤 문장은 피드백을 남길 위치를 함께 설명했다. 쉼표만 모두 지우는 데서 끝내지 않고 각 문장의 역할을 따랐다. 결과에 `~습니다`가 반복돼도 이를 피하려고 다시 합치지 않는다. 이 예처럼 반드시 ‘짧게 두 문장 + 길게 한 문장’으로 맞추라는 뜻도 아니다.

다음 수정은 피한다.

| 피할 수정 | 문제 |
| --- | --- |
| `승인이 나면 파일을 공개한다. 링크를 보낸다.` | 승인 조건이 링크 발송에도 걸리는지 흐려짐 |
| `초안을 작성하므로 검토를 진행한다.` | 원문에 없는 원인 관계 추가 |
| `제목은 짧게 쓴다. 설명은 아주 쉽게 풀어서 작성한다.` | 길이를 달리하려고 표현을 불필요하게 늘림 |
| 모든 `~하며,`를 `~하고`로 치환 | 문장 구조의 반복은 남을 수 있음 |

## 검증할 때는 뜻과 보존 사례를 확인한다

이 문서는 자동 탐지기가 아니다. 스킬을 수정한 뒤 위 사례를 직접 적용하고 다음 기준으로 검토한다. 특정 문구와 일치하는지는 합격 조건이 아니다.

- 쉼표 삭제·문장 분리·공통 성분 묶기를 문맥에 맞게 골랐는가.
- 조건 범위·행동 순서·주체·부정·가능성·의무가 바뀌지 않았는가.
- 실제 대조·열거·숫자·인용과 자연스러운 단문을 보존했는가.
- 문단 예시에서 쉼표 개수만 줄이고 같은 틀을 그대로 남기지 않았는가.
- `voice-samples.md`의 사용자 승인 원문은 바꾸지 않았는가.

검증 범위는 교정 원칙과 예시의 일관성이다. 이 점검만으로 모든 후속 생성의 문체가 개선됐다고 주장하지 않는다.
