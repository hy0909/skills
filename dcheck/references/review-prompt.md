# 검토 에이전트 프롬프트 틀

`<...>` 자리를 채워서 general-purpose 서브에이전트에 넘긴다. 사이클마다 새 에이전트를 띄운다.

```
읽기 전용 검토(<n>회차, 초점: <정책 반영 | 문서 간 교차 | 요구사항 테이블 세부 | 링크·버전·표 | 전체 재검토>). 파일 수정 금지, GitHub 쓰기 금지. 냉철하게, 인용 근거만. 한국어로 보고.

대상: <워크트리 절대 경로> (<저장소 이름>, origin/main 최신). plan/ 아래 .md 전부, deprecated/plan/**/*.md, README.md, plan/README.md를 읽어라. 큰 파일(<파일명 약 n줄>)도 전체를 읽어라.

확정 정책(<날짜> 사용자 정리). 문서가 이대로 돼 있어야 한다:
D1. <정책 문장>
D2. <정책 문장>
…
※ 같은 주제에 결정이 둘이면: "<옛 결정>"과 "<새 결정>"이 있다. 문서에 어느 쪽이 적혀 있는지 모두 인용해 보고하라(판정은 내가 한다).

보고할 것:
A. D1~Dn 각각에 대해 (1) 정책을 적은 문서·줄 인용, (2) 정책과 어긋나는 문장 전부(file:line, 원문 인용, 왜 틀렸는지, 고칠 문장 제안), (3) 정책이 들어가야 하는데 아예 없는 문서(어느 절·요구사항 행에 넣어야 하는지 제안).
B. 문서 사이에 서로 다른 말을 하는 곳(같은 주제를 두 문서가 다르게 적음). 한 쌍씩 인용.
C. 상대 링크 파일 존재 여부, yaml version과 변경 이력 최상단 일치, 표 칸 수, 괄호·백틱 짝.
심각도(높음/중간/낮음)와 함께. 변경 이력·"변경 전" 칸은 역사 기록으로 따로 분리. 추측하지 말고, 없으면 없다고 써라.
```

## 자주 틀리는 것(에이전트 보고를 믿기 전에 확인)

- 브랜치 중간 커밋 버전을 main 버전으로 착각한다. `git show origin/main:<path> | grep '^version'`으로 직접 본다.
- 다른 저장소 이슈·PR 번호를 "없다"고 한다. `gh api repos/<owner>/<repo>/issues/<n>`으로 직접 본다.
- 역사 기록(변경 이력, 변경 전 칸)을 현재 문장으로 세는 경우가 있다.
- 줄바꿈으로 나뉜 괄호를 짝이 안 맞는다고 한다.
